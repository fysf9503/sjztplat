三、Nginx 配置

3.1 Nginx 配置文件

将以下配置写入 Nginx 的 server 块中（通常在 /etc/nginx/conf.d/data-platform.conf 或 /etc/nginx/nginx.conf）：

# 数据中台前端 + API 代理
server {
    listen       80;
    server_name  _;  # 替换为你的域名或 IP

    # 前端静态资源
    root   /usr/share/nginx/html/data-platform;
    index  index.html;

    # Vue Router History 模式：所有前端路由回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ===== API 代理（全部转发到网关 8601）=====

    # 认证服务
    location /auth/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 系统管理
    location /system/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 数据开发
    location /dev/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 调度管理
    location /schedule/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 数据质量
    location /quality/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 实时任务
    location /realtime/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 数据集成
    location /integration/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 数据治理
    location /governance/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 数据血缘
    location /lineage/ {
        proxy_pass http://GATEWAY_IP:8601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # gzip 压缩
    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;
}
重要：将 GATEWAY_IP 替换为你部署网关的服务器 IP 地址。如果 Nginx 和网关在同一台机器上，可以使用 127.0.0.1。

3.2 前端文件目录

将 dist/ 目录内容上传到服务器 /usr/share/nginx/html/data-platform/：

# 在本地构建后上传
scp -r dist/* user@server:/usr/share/nginx/html/data-platform/

七、数据开发工作流（重点）

这是本平台的核心功能，完整流程如下：

创建开发任务
→
创建工作流
→
添加任务到工作流
→
自动检测依赖
→
确认/手动添加依赖
→
发布到 DS
→
上线调度

步骤 1：创建开发任务（/dev/tasks）

在「数据开发 > 开发任务」页面点击「新建任务」：

  • 任务名称：如 ods_user_sync
  • 任务类型：FLINK / SQL / SHELL / PYTHON / CUSTOM
  • 源表：JSON 数组，如 ["external.user_log"]（任务读取的表）
  • 目标表：JSON 数组，如 ["ods.user_log"]（任务写入的表）
  • 任务参数：DS taskParams JSON 格式
关键概念：源表和目标表用于自动依赖推导。任务 A 的源表 ∩ 任务 B 的目标表 ≠ 空集 → A 依赖 B。

步骤 2：创建工作流（/dev/workflow）

在「数据开发 > 工作流编排」页面点击「新建工作流」：

  • 名称：如 数仓ETL流水线
  • Cron：如 0 0 2 * * ?（每天凌晨2点）

步骤 3：添加任务到工作流

选中工作流后，在左侧任务列表点击「添加任务」，从弹窗中搜索并添加已创建的开发任务。

步骤 4：自动检测依赖

点击顶部「自动检测依赖」按钮，系统基于表血缘关系自动推导依赖建议：

  • 系统返回建议列表，显示匹配的表名
  • 建议仅作参考，不自动保存

步骤 5：确认/手动添加依赖

在下方 Tab 面板操作：

Tab操作说明
依赖建议 勾选要确认的建议 → 点击「确认依赖关系」 自动检测结果，需用户确认后生效
手动添加 左侧选中任务 → 搜索前置任务 → 点击「添加为前置」 手动指定依赖，可搜索任务名
当前依赖 查看所有已配置的依赖 → 可移除 展示当前完整的依赖列表

步骤 6：发布到 DolphinScheduler

点击顶部「发布到DS」按钮：

发布前校验：所有任务的依赖状态必须为「已确认」或「手动」。「待确认」状态的任务会被拒绝发布。

发布后系统自动构建 DS taskDefinitionJson + taskRelationJson，调用 DS API 创建完整 DAG 工作流。

步骤 7：上线调度

发布成功后，点击「上线」按钮，系统创建 DS 调度（Cron 表达式）并上线。DS 将按 Cron 自动执行 DAG。

DAG 可视化

页面中间区域展示 ECharts DAG 图，节点为任务，带箭头的边为依赖关系。不同任务类型用不同颜色区分。

八、常见问题

Q1: 页面空白 / 404

检查 Nginx try_files 配置是否正确，确保 SPA History 模式路由回退到 index.html。

Q2: API 请求 502 / 504

检查：

  • 网关服务（8601 端口）是否已启动
  • Nginx 的 proxy_pass 地址是否正确
  • 防火墙是否放行 8601 端口

Q3: 登录提示「请求失败」

检查 /auth/ 代理是否正确指向网关。登录接口为 POST /auth/auth/login。

Q4: 数据开发功能无法使用

确保网关已添加 /dev/** 和 /schedule/** 路由，且 system-service 已注册到 Nacos。

Q5: 更新前端版本

# 本地重新构建
cd data-ui && npm run build

# 上传覆盖
scp -r dist/* user@server:/usr/share/nginx/html/data-platform/

# Nginx 无需重启，静态文件直接生效
